# Day 1 회고

## 오늘의 목표

- FlashScale의 프로젝트 목표와 핵심 실험을 문서화한다.
- v1 포함 범위와 제외 범위를 명확히 한다.
- 이후 작업에 사용할 디렉터리 구조와 협업 규칙, 문서 템플릿을 준비한다.
- 초기 변경사항을 Git에 커밋하고 원격 저장소에 게시한다.

## 완료한 작업

- `ticketing-api`, `predictor`, `infra`, `load-tests`, `monitoring`, `scripts`, `docs` 디렉터리 구조를 준비했다.
- 프로젝트 차터에 문제 정의, 세 가지 scaling 전략, 핵심 측정값, v1 포함·제외 범위와 30일 완료 기준을 기록했다.
- 루트에 `AGENTS.md`를 추가해 작업 범위, 아키텍처, 검증 및 변경 정책을 정리했다.
- Task, ADR, 일일 회고 템플릿을 추가했다.
- `.gitignore`에 `.DS_Store`를 등록하고 기존 `.DS_Store` 파일은 로컬에서 삭제하지 않은 채 Git 추적만 해제했다.
- Day 1 변경사항을 `cc1cdf9` 커밋으로 만들고 `agent/day-01-bootstrap` 원격 브랜치에 푸시했다.

## 이해한 개념

- FlashScale v1의 핵심은 동일한 부하 시나리오에서 고정 replica, CPU 기반 HPA, 트래픽 예측 기반 scaling을 비교하는 것이다.
- 평가에는 요청 성공률, p95/p99 latency, 처리량, 중복 예약 여부, replica와 리소스 사용량, 스케일 아웃 시점, 예측 오차가 필요하다.
- 기능을 추가할 때는 활성 task와 프로젝트 차터를 함께 확인하고, v1 제외 범위를 임의로 확장하지 않아야 한다.
- `.gitignore`에 파일 패턴을 추가해도 이미 추적 중인 파일은 자동으로 제외되지 않으므로 Git 인덱스에서 별도로 추적을 해제해야 한다.

## 막힌 부분과 해결 과정

- Codex 샌드박스에서는 macOS keyring의 GitHub 인증을 읽지 못해 `gh auth status`가 실패했다. 샌드박스 밖의 keyring 접근을 허용한 뒤 인증 상태를 확인했다.
- Git 인덱스가 샌드박스에서 쓰기 제한되어 스테이징이 실패했다. Git 인덱스 수정 권한을 승인받아 `.DS_Store` 추적 해제와 변경사항 스테이징을 완료했다.

## Codex가 제안했지만 채택하지 않은 내용

- Day 1 체크리스트 외의 기준으로 완료 여부를 확대해서 판단하지 않았다.

## 검증 결과

- `git diff --cached --check`가 통과했다.
- 루트와 `infra`의 `.DS_Store`가 `.gitignore` 규칙에 의해 무시되는 것을 확인했다.
- 두 `.DS_Store` 파일이 Git 추적 목록에서 제거된 것을 확인했다.
- 커밋 후 작업 트리가 깨끗하고 로컬 브랜치가 원격 `agent/day-01-bootstrap` 브랜치를 추적하는 것을 확인했다.
- Day 1 체크리스트의 모든 산출물을 다시 확인하고 완료로 표시했다.
- `./scripts/verify.sh`는 존재하지 않아 실행하지 못했다.

## 남은 위험

- 완료 전 전체 검증에 사용하도록 규정된 `./scripts/verify.sh`가 아직 없다.
- Day 1 문서 보완 변경사항은 PR 검토와 `main` 병합이 필요하다.

## 내일 첫 번째 작업

- 다음 활성 task를 확인하고 프로젝트 차터와 함께 읽은 뒤 작업 범위와 acceptance criteria를 정리한다.
